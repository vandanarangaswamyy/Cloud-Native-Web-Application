# AWS Networking + Application Infrastructure with Terraform

This project provisions the required AWS networking and application infrastructure for the Cloud Native Web Application, including VPC, subnets, ALB, EC2 Auto Scaling, RDS, SNS, Lambda, KMS encryption, Route53 DNS, and SSL/TLS certificates.

## Features

### Networking

The Terraform configuration sets up:

- A Virtual Private Cloud (VPC)
- 3 public + 3 private subnets across multiple AZs
- Internet Gateway (IGW) attached to VPC
- Public route table → IGW
- Private route table for RDS + EC2
- No public IPs assigned to EC2
- SSH access fully disabled (required by assignment)

### Load Balancer & HTTPS

- Application Load Balancer (ALB) deployed in public subnets
- EC2 instances only accessible via ALB
- HTTPS listener (port 443) with:
    - **dev**: AWS ACM certificate
    - **demo**: ZeroSSL imported certificate
- ALB forwards HTTPS → HTTP:8000 to EC2 private instances
- `/healthz` route configured for ALB health checks

**ZeroSSL Certificate Import Command (Demo):**

```bash
aws acm import-certificate \
  --certificate fileb://certificate.crt \
  --certificate-chain fileb://ca_bundle.crt \
  --private-key fileb://private.key \
  --region us-east-2 \
  --profile demo
```

### RDS + Secrets Manager

- MySQL RDS instance in private subnets
- No public access
- Encrypted with custom KMS key (`rds_kms_key`)
- DB password auto-generated by Terraform
- Stored in Secrets Manager with KMS encryption
- EC2 retrieves password using `user-data.sh` during boot

### AWS KMS (Mandatory Requirement)

Four unique KMS keys are created:

| Key | Used For |
|-----|----------|
| `ec2_kms_key` | EC2 EBS volume encryption |
| `rds_kms_key` | RDS encryption |
| `s3_kms_key` | S3 bucket encryption |
| `secrets_kms_key` | Secrets Manager encryption |

All keys have automatic 90-day rotation enabled.

### Email Verification (SNS → Lambda → SendGrid)

- When user registers, the webapp publishes an SNS message
- SNS triggers a Lambda function
- Lambda sends verification email using SendGrid API
- Lambda packaged and stored in S3 bucket
- IAM roles and Managed Policies included to:
    - Allow SNS invocation
    - Allow logging
    - Allow Secrets Manager GetSecretValue

### Autoscaling

- Auto Scaling Group (ASG) with Launch Template
- Launch Template references latest AMI created via CI/CD
- ASG performs Instance Refresh during deployment
- ALB health checks ensure safe rollout

### DNS & SSL

- Route53 Hosted Zones for dev and demo
- A record → ALB DNS alias
- Public Namecheap domain delegating to AWS NS records

## Prerequisites

- Terraform >= 1.5.0
- AWS CLI installed and configured with two profiles:
    - `dev`
    - `demo`
- Namecheap (or similar) domain for Route53 delegation
- GitHub Actions secrets for AMI pipeline
- SendGrid API key

## Setup

### 1. Initialize Terraform

```bash
terraform init
```

### 2. Format and validate

```bash
terraform fmt -recursive
terraform validate
```

### 3. Plan

```bash
terraform plan -var-file="terraform.tfvars"
```

### 4. Apply

```bash
terraform apply -var-file="terraform.tfvars" -auto-approve
```

### 5. Destroy

```bash
terraform destroy -var-file="terraform.tfvars" -auto-approve
```

## Continuous Integration (CI)

The repo includes a PR workflow:

- `terraform fmt -check -recursive`
- `terraform validate`

Enforced using GitHub branch protection.

Assignment 8 CI/CD (AMI workflow) handled in the webapp repo, not here.

## Variables

Defined in `variables.tf` and provided via `terraform.tfvars`:

| Variable | Description | Example |
|----------|-------------|---------|
| `aws_profile` | AWS CLI profile to use | `"dev"` |
| `target_account` | Target AWS account (dev or demo) | `"demo"` |
| `region` | AWS region | `"us-east-2"` |
| `vpc_name` | VPC name | `"assignment-vpc-a"` |
| `vpc_cidr` | CIDR for VPC | `"10.50.0.0/16"` |
| `subnet_newbits` | Subnet sizing | `8` |
| `tags` | Common tags | `{ Project="csye6225" }` |
| `webapp_domain` | DNS domain for ALB | `"dev.vandanarangaswamy.com"` |
| `sns_topic_arn` | SNS ARN (varies per account) | `"arn:aws:sns:us-east-2:<ACCOUNT>:topic"` |
| `verification_url` | URL sent in verification emails | `"https://dev.vandanarangaswamy.com"` |

### Example `terraform.tfvars`

```hcl
aws_profile    = "dev"
target_account = "dev"
region         = "us-east-2"

vpc_name       = "assignment-vpc-a"
vpc_cidr       = "10.50.0.0/16"
subnet_newbits = 8

webapp_domain     = "dev.vandanarangaswamy.com"
sns_topic_arn     = "arn:aws:sns:us-east-2:<DEV-ID>:user-verification-topic"
verification_url  = "https://dev.vandanarangaswamy.com"

tags = {
  Project = "csye6225"
  Owner   = "Vandana"
}
```

For **demo**, only these change:

```hcl
aws_profile    = "demo"
target_account = "demo"
webapp_domain  = "demo.vandanarangaswamy.com"
sns_topic_arn  = "arn:aws:sns:us-east-2:<DEMO-ID>:user-verification-topic"
verification_url = "https://demo.vandanarangaswamy.com"
```
